# Customer Portal — Project Context for Claude Code

This is Summit Sensory Gym's customer-facing order portal (Next.js, `pages/`), backed entirely by Monday.com (no separate database — `lib/monday.js` is the single data layer). Production is `portal.summitsensory.com`, deployed via Vercel from this repo's `main` branch; `staging` gets its own private Vercel Preview URL for testing risky changes before merging to `main`.

## Recovered design artifact

`claude-project-docs/design-mockups/portal-color-selection-preview.html` is the actual, unaltered HTML of the most recent published preview from the redesign work (the "Portal Color Selection Preview" artifact referenced in `color-selection-redesign-proposal-2026-08-22.md`'s final entry) — a real, working Cardinal (131 real photos) + Prismatic (428 colors) picker embedded in a recreation of the real portal chrome. Recovered 2026-09-01 by reading the published artifact link directly, not reconstructed from the docs. Open it in a browser to interact with it directly instead of trusting the design log's prose.

The earlier, broader `mockup.html` (the one that also covered vinyl, Ball Pit, Ball Pit Balls, and Palisades) was never published as a persistent artifact — it only ever existed as direct file downloads in past sessions that have since ended, and could not be recovered. Per the design logs' own repeated "Still open" notes, those 4 other product lines were never actually sourced with real supplier data in the first place (vinyl used illustrative CSS colors with no real photos ever found; Ball Pit/Ball Pit Balls/Palisades had zero real color data at any point) — so there isn't a "real" version of that file to verify against yet, unlike Cardinal/Prismatic.

## Things every session should know without being told

- **Claude does not run git commands against this repo from Cowork/the device bridge** — only file edits. Whoever picks up a change here (you, running natively, or Bryan via GitHub Desktop) needs to review, commit, and push it. This repo has a real history of large uncommitted backlogs building up across sessions — check `git status` early and flag anything surprising.
- **The live production Color Selection tab is still a Jotform iframe** for any productType not yet migrated. A real native picker exists and works for Structure & Frame Paint + Mat & Pad Color, but only on branch `claude/color-selection-redesign` — not merged to `staging`/`main`, not deployed. Check which state you're actually looking at before assuming either one. See `color-selection-native-picker-build-2026-09-01.md`.
- **Monday.com is the only datastore.** Column IDs are mapped in `lib/monday.js`'s `COLS` object; don't assume a "database migration" pattern applies here — changes to what's tracked mean either a new Monday column or a new board.
- **`productType` matching is exact-string, case-sensitive, no normalization**, anywhere in the codebase (`lib/monday.js`, `pages/portal/index.js`, `pages/api/jotform/webhook.js`, `lib/colorRequirements.js`). Always check `productType`/`productTypes` values against the *real* Monday column values on the Manufacturing Process board (6533700776, column `color_mkvw7b8`) before trusting an env var or hardcoded list — this exact class of bug has already caused multiple real incidents (see `build-and-fix-2026-08-27.md`).
- **The completion-tracking decision is resolved (Option 4, confirmed by Bryan 2026-09-01) — but Option 4 itself is NOT built yet.** Don't treat "the decision is made" as "the work is done." See `color-selection-native-picker-build-2026-09-01.md` for exactly what Stage 1/2/3 still require, and don't create/edit live Monday boards for this (Stage 1) without checking with Bryan first — that's a separate checkpoint from the architecture decision itself.
- **A real, independent code review already found real bugs in the color-picker work** — some fixed, some still open (documented in `color-selection-native-picker-build-2026-09-01.md`'s table). Read that table before assuming the branch is clean.
