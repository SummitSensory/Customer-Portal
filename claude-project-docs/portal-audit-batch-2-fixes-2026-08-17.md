# Customer Portal — Second Audit Batch: 11 Additional Bugs Fixed (2026-08-17)

Follow-up to `claude/kalen-siddens-portal-audit-2026-08-17.md`. Bryan asked whether other issues existed beyond the Kalen Siddens complaint. A broader audit covered the admin dashboard, auth, shipment tracking/webhooks, referrals, Jotform routing, and invites — surfacing 11 more real, verified bugs (not hypothetical), which were fixed in the exact order presented per Bryan's explicit instruction to leave no loose ends.

## The 11 fixes

1. **Accessory webhook secret check failed open.** `pages/api/monday/accessory-webhook.js` used `if (secret && req.query.secret !== secret)` — with `MONDAY_ACCESSORY_WEBHOOK_SECRET` unset in Vercel, authorization was skipped entirely and the endpoint accepted requests from anyone. Fixed to fail closed (`if (!secret || ...)`), mirroring the AfterShip webhook's `isAuthorized()`.
   **⚠️ Action needed:** confirm `MONDAY_ACCESSORY_WEBHOOK_SECRET` is set in Vercel and the registered Monday webhook URL already includes `?secret=<value>` — otherwise this endpoint will now reject real Monday events too. This session could not read Vercel env var values to verify independently.
2. **UGC photo/video attach was silently broken.** `attachUgcFile()` sent the Jotform file URL as a JSON `$file: String!` variable — Monday's `add_file_to_column` requires a real multipart upload (`file: File!`) to `/v2/file`. Every Photo & Video Showcase submission "succeeded" (logged, reward-tallied) without ever actually attaching a file. Fixed to download the file and upload via the existing multipart `uploadFileToColumn()` helper. Also fixed the Jotform webhook call site so only files that actually attach get counted/logged/credited, and a submission where every attach fails now returns a real error instead of a false success.
3. **Admin file-upload had the identical bug.** `addFileToOrder()` — same JSON-vs-multipart fix. Its call site (`pages/api/monday/files.js`) already had correct error handling, so no change needed there.
4. **Order-by-email lookups weren't sorted by recency.** `getOrderByEmail()`/`getOrdersByEmail()` returned orders in whatever order Monday's API happened to give them — a repeat customer could land on an old order instead of their newest at portal login or Jotform routing. Now sorted most-recent-first by `createdAt`.
5. **Hard 500-item page caps silently truncated large boards.** `getAllOrders`, `findAccessorySubitemByTracking`, `findOrderByFreightTracking`, and `getAllAccessoryItems` all used a single `items_page(limit: 500)` with no pagination (and `getAllOrders` took a caller-supplied limit as low as 100 for the admin dashboard, 200 for the reminders cron). Added a shared `fetchAllBoardItems()` helper that pages through Monday's cursor-based `items_page`/`next_items_page` in full; all four functions (and the two cron jobs that called `getAllOrders`) now see the complete board regardless of size.
6. **Freight-update email + dedupe tag write weren't atomic.** If the AfterShip webhook's customer email sent but the "last notified status" tag write failed, the next matching checkpoint would re-send a duplicate email with no record the first had gone out. Split into two steps: an email failure now skips the tag write (so the next attempt retries the send); a tag-write failure after a successful send is logged loudly with the exact manual Monday fix needed, instead of vanishing into the outer catch.
7. **Same non-atomic pattern in the manual portal-invite endpoint.** A Monday log-write failure after a successfully-sent invite reported "Failed to send invitation" to staff — who would then resend and duplicate the customer email. Now returns success (with a warning) when only the log write fails.
8. **AfterShip payload-shape handling had no logging.** `payload.msg` was the assumed shape (`payload.data.tracking` an unverified fallback), with silent fallthrough if neither matched. Now logs which shape was used and warns loudly on a genuinely unmatched shape, so a real AfterShip format change is visible in logs instead of quietly no-op'ing.
9. **Jotform email extraction was fragile.** `extractEmail()` only checked top-level strings or one level of `{answer: ...}` nesting, with weak "contains @ and ." validation. Rewritten to recurse through nested objects/arrays (same approach as the existing `extractShowcaseFiles()`) using a real email-pattern regex.
10. **Multi-form tabs completed on the first form, not all of them.** A Required Documents (or Color Selections) tab backed by more than one Jotform form flipped to ✅ the instant any single mapped form arrived. Now embeds the form ID in the completion tag and checks Monday's update history for every other form mapped to that tab before marking the section complete.
11. **Team notification emails linked to a dead-end.** `notifyTeamNewReferral`/`notifyTeamUgcThreshold`'s CTA buttons both pointed at the generic `/admin` dashboard instead of the actual Monday item. Now build direct Monday pulse links (`https://{account}.monday.com/boards/{boardId}/pulses/{itemId}`, the same pattern already used in `createReferralItem()`), falling back to `/admin` only if an item ID isn't available. Call sites (`referral/submit.js`, `jotform/webhook.js`) updated to pass the item ID through.
